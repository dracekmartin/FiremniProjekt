# Schůzka se Škodou, 23. 9. 2026, 12:00

Ověřuje náročnost práce a shodu se specifikací, ne jestli EDISON2 funguje ("jesli to odpovídá tomu,
co se od Vás z hlediska toho předmětu očekává").

Na úvod: každý soubor jiný typ problému (transakce nad FS, protokol přes hranici .NET a Caché, interop
s legacy procesy, souběžnost, distribuovaný stav session). EDISONMAIN2, EDControls a EDUPDATE2 jsou moje,
TemplateDesigner je kolegův a do odevzdání nepatří.

Tři první jsou na průchod do hloubky, čtyřka a pětka jako doplněk, kdyby zbyl čas nebo se ptal jinam.

## Demo (cca 15 min)

1. Shell z `C:\Edison`, ne z Visual Studia.
2. **Login, výběr firmy.** Přepnutí firmy za běhu uvolňuje zámky staré firmy. Můstek na soubor 5.
3. Strom modulů: fulltext, oblíbené, spuštěné moduly. Definice se servíruje z Caché, ne z XML v klientovi.
4. **Profil uživatele.** Definice polí i validace jsou v Caché třídě, klient staví UI. Můstek na soubor 2.
5. **Legacy agenda z nového shellu.** Druhý klik na tentýž modul jen přenese focus. Můstek na soubor 3.
6. Plocha se zástupci, mini-apps, news panel.
7. Update **neukazovat živě**, jen log z reálného běhu a vedle scénářový test.
8. `dotnet test EDISON2.sln`, přes 2 800 testů. Pustit před demem, běžící shell zamyká DLL v `bin\Debug`.

## 4. MLRest: souběžná volání a obrana proti regresi

Tři malé soubory, dohromady ~200 řádků, jedna uzavřená myšlenka.

| soubor | ř. | |
| --- | --- | --- |
| `EDControls/dotnet/RestCallRunner.cs` (25 ř.) | 9-15 | proč je klon nutnost, ne kosmetika |
| | 20-23 | snapshot instance na UI threadu |
| `EDControls/dotnet/MLRestAdapter.cs` (75 ř.) | 19-24 | jediné místo překladu stavu na výjimku |
| | 52-74 | `With()` klonuje identitu, žádná mutace sdílené instance |
| `EDControls.Tests/MLRestAdapterWithTests.cs` | 6-9, 13-20 | reflection drift test s allow-listem |
| | 32-33, 46-47 | nepodporovaný typ test rozbije, aby property nevypadla z pokrytí |

- Sdílená instance nese `RestStatus` posledního requestu. Dvě souběžná volání si stavy prohodí, výsledek je
  spolknutá chyba nebo cizí výjimka.
- Proto všechno paralelní jede na klonu. Klon má stejný GUID, pro server je to tatáž session, a každý
  souběžný request obsluhuje jiný Caché proces, takže si nešlapou ani po `^||ML`.
- Identita se kopíruje ručně, což je křehké. Reflection test hlídá, že na novou property nikdo nezapomene.
- Snapshot na volajícím threadu drží celou dávku proti téže session i při přepnutí firmy.

Spec: **T4**, **N12**.

## 5. Session lifecycle a zámky

Specifikace popisuje legacy inaktivitu jako "effectively impossible to solve" s dopadem na licencování,
updaty i agendy. Tohle je kód, který ten problém řeší.

| soubor | ř. | |
| --- | --- | --- |
| `EDISONMAIN2/dotnet/Startup/SessionLogout.cs` (47 ř.) | 7-14 | zámky nezaniknou se spojením, legacy moduly zamykají pod shell GUID |
| | 18-23 | logout jede na klonu s `CacheLocks=0` |
| | 34-40 | ACTIVITY logout nezávislý na `LockClearExt` |
| `EDISONMAIN2/dotnet/Startup/SessionFactory.cs` | 17-22 | jediné místo skládání session, startup i switch uživatele |
| | 40-45 | deterministický GUID v DEBUG |
| `EDISONMAIN2/dotnet/Startup/LogoutWatcher.cs` (86 ř.) | 11-15 | cooperative logout pollem, parita s legacy `frmNoMDI.MainTimerProc` |

- Zámky se zánikem spojení nezaniknou, musí se uklidit explicitně. Pod GUID shellu zamykají i hostované
  legacy moduly, které se zavírají killem, takže jejich zámky uklidí až logout shellu.
- ACTIVITY logout a business zámky jsou schválně nezávislé: server-side idle reaper bere jen ACTIVITY,
  takže selhání prvního kroku nesmí nechat viset druhé.
- Logout běží na klonu s `CacheLocks=0`, jinak by request padl na `LockExist`.
- V DEBUG deterministický GUID, protože Stop Debugging zámek neuvolní. Příští spuštění klíč přepíše,
  místo aby se zámky hromadily a falešně nafukovaly licenční počet.
- Startup i přihlášení jiného uživatele jdou stejnou cestou. Drift by znamenal službu ukazující na starou session.

Doprovod: `SessionLogoutTests.cs`, `SessionFactoryTests.cs`, `LogoutWatcherTests.cs`, `SessionSwitcherTests.cs`.

Spec: **S8**, **S18**, **L3**, **N1**.
